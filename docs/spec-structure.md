# Spec Document Structure

A spec describes **what the system must do**, not how it is implemented.

## 1. Overview
- Purpose
- Scope
- Actors

## 2. Requirements
- Functional requirements
- Business rules
- Non-functional requirements

## 3. Behavior
- Main use cases
- System flows
- Error / edge cases

## 4. Contracts
- API contracts
- Data models
- Events

## 5. Constraints
- Technical/business constraints
- Out of scope

## 6. Acceptance Criteria
- Conditions that determine whether the requirement is correctly implemented.

---

**Spec = What + Behavior + Contract + Acceptance Criteria**
